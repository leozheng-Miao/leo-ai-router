# LeoAI Router 用户端前端重构设计

日期：2026-05-20

## 目标

重构 LeoAI Router 用户端前端展示，使核心页面统一为白底 SaaS 控制台风格，并贴近参考图中的产品首页、聊天工作台、充值账单页面。第一阶段完成用户端，完成并验证后再进入管理后台重构。

## 范围

第一阶段覆盖：

- 首页 `/`
- 控制台概览 `/dashboard`
- 在线对话 `/chat`
- AI 绘图 `/images`
- 会员充值 `/membership`
- 个人中心 `/profile`
- API Keys `/keys`
- 使用统计或账单历史 `/history`

第二阶段在第一阶段完成后覆盖管理后台：

- 提供者管理 `/providers`
- 模型管理 `/models`
- 插件管理 `/plugins`
- 用户管理 `/users`
- 角色权限 `/roles`

## 技术栈

保留：

- Vue 3

自研用户端核心视觉组件：

- Button

- PlanCard
- SidebarNav

- ComposerShell
- BillingSummary

## 导航结构

顶部导航：

- 首页
- 控制台
- 在线对话
- AI 绘图
- 会员充值
- 文档

登录用户头像菜单：

- 个人中心

## 视觉规范

整体采用浅色 SaaS 控制台风格：

- 页面背景：`#F6F8FC`
- 面板背景：`#FFFFFF`
- 弱面板背景：`#F9FAFD`
- 主色：`#245BFF`
- 主色浅背景：`#EEF3FF`
- 主文本：`#0F172A`
- 次文本：`#667085`
- 弱文本：`#98A2B3`
- 边框：`#E6EAF2`
- 成功：`#12B76A`
- 警告：`#F79009`
- 危险：`#F04438`

尺寸规范：

- 普通卡片圆角：8px
- 按钮与输入圆角：6px
- 页面内容最大宽度：约 1440px
- 控制台和聊天页面允许全宽布局
- 普通卡片以细边框为主，少用重阴影
- 阴影只用于浮层、弹窗、重点面板

响应式要求：

- 桌面端优先，信息密度贴近参考图
- 移动端保证不重叠、可滚动、主要操作可触达
- 不做复杂移动端专属交互

## 页面设计

### 首页

首页对齐参考图左侧产品展示：

- 首屏包含产品定位、主操作按钮、文档按钮、SDK 代码示例
- 展示 DeepSeek、通义千问、智谱 GLM、OpenAI、Gemini 等模型健康条
- 下方展示平台指标、路由策略概览、请求趋势、模型调用占比、最新动态
- 未登录用户主操作进入注册或登录
- 登录用户可进入控制台

### 控制台概览

新增登录后概览页面：

- 接入模型数量
- 路由策略数量
- 今日请求数
- 成功率
- 平均延迟
- 用户数或账号额度概览
- 路由策略表
- 请求趋势图
- 模型调用占比
- 最新动态

数据优先复用现有统计接口；接口缺失时先使用现有可得数据和清晰空状态，不新增后端统计逻辑作为第一阶段必做项。

### 在线对话

聊天页改为三栏工作台：

- 左侧：会话列表、新建会话、搜索、回收站或删除入口
- 中间：消息流、推理内容折叠、Markdown 渲染、复制、流式状态、输入区
- 右侧：路由配置、模型选择、会员锁定态、深度思考、温度等参数

保留现有业务逻辑：

- conversation API
- `routing_strategy`
- 固定模型
- 深度思考
- SSE 流式输出
- 历史消息加载
- Markdown 渲染
- 停止生成
- 会话删除
- 会员额度与模型锁定

### AI 绘图

AI 绘图页统一为工作台风格：

- 生成提示词输入区
- 模型选择区
- 参数区
- 积分和会员限制提示
- 生成结果展示区
- 历史或空状态

保留现有 Gemini/OpenAI/Qwen 图片模型能力边界，不让 UI 暗示后端不支持的参数会生效。

### 会员充值

会员充值页对齐参考图右下：

- 左侧用户中心导航
- 顶部账号权益概览
- 中间为套餐订阅和积分购买 tab
- 右侧固定支付摘要
- 支付方式保留支付宝、Stripe、微信未开放状态

业务语义保持：

- 套餐负责聊天和 API 中转权益
- 积分负责图片生成消耗
- 支付成功后权益到账

### 个人中心、API Keys、历史记录

统一放入用户中心壳层：

- 左侧导航
- 右侧内容区域
- 表单、密钥列表、账单记录、使用记录统一面板样式

个人中心不恢复旧 token 资产展示。旧后端成本统计与历史兼容逻辑不动。

## 数据流与业务约束

本次前端重构不改：

- 后端 API 契约
- 模型调用逻辑
- 会员权益校验
- 积分扣费逻辑
- SSE 协议处理
- Markdown 渲染契约
- 认证 token 刷新逻辑
- 后台成本统计逻辑

模型展示规则：

- 所有启用模型对用户可见
- 可用性由会员等级、积分和后端权益校验决定
- 前端展示锁定态，后端继续兜底校验

## 错误处理

统一交互：

- 加载失败使用 ErrorPanel，提供重试按钮
- 空数据使用 EmptyState
- 删除会话、删除 API Key 等危险操作使用确认交互
- 支付失败、创建失败、权限不足使用 Ant Message 或 Modal
- 流式生成保留 loading、停止、失败提示

## 实施顺序

第一阶段建议顺序：

1. 建立 design tokens、全局样式和基础视觉组件
2. 重构 App Shell、顶部导航、用户中心壳层
3. 新增 Dashboard 页面
4. 重构 Home 页面
5. 重构 Chat 页面
6. 重构 Membership 页面
7. 重构 Image 页面
8. 统一 Profile、API Keys、History
9. 全量用户端验证

第二阶段在第一阶段完成后开始：

1. 抽象管理后台列表页布局
2. 重构 Provider、Model、Plugin 管理页
3. 重构 User、Role 管理页
4. 全量后台验证

## 验证

每个任务后：

- `npm run type-check`

阶段性：

- `npm run build-only`

用户端全部完成后：

- 启动本地 dev server
- 检查 `/`
- 检查 `/dashboard`
- 检查 `/chat`
- 检查 `/images`
- 检查 `/membership`
- 检查 `/profile`
- 检查 `/keys`
- 检查 `/history`

视觉检查：

- 对照用户上传的 PNG 检查布局、密度、颜色、边框、卡片、导航、聊天三栏、充值支付摘要
- 如需要，再将页面捕获到 Figma 做补充校验

第一阶段不做：

- 后端接口重构
- 权限系统重写
- 支付流程重写
- 模型调用逻辑修改
- 新增复杂移动端专属交互
- 管理后台重构
- 替换 Vue、Vite、Pinia、Vue Router
